1. What to install

You need Python 3.9+ on your laptop. Then, from the project folder, install everything with one command:

pip install -r requirements.txt

That installs the following packages:

PackageUsed forRequired?
streamlitThe dashboard UI itselfYes
pandasStoring/aggregating session data, CSV exportYes
plotlyAll charts (RTT lines, bar charts, heatmaps, box plots)Yes
numpyFloor-plan heatmap interpolation mathYes
PillowDrawing the floor-plan image + heatmap overlayYes
streamlit-image-coordinatesClick-to-place points on the floor planOptional — falls back to sliders if missing
No other installs are needed. Everything else (sqlite3, subprocess, socket, urllib, statistics, concurrent.futures) is part of Python's standard library — nothing extra to install for those.

3. How to run it

Step 1 — quick sanity check (recommended before the dashboard)

python core.py --duration 15

Confirms your OS, gateway detection, ping parsing, and DNS/HTTP checks all work before you rely on the dashboard.

Step 2 — launch the dashboard

streamlit run app.py

Opens automatically at http://localhost:8501.

Stay connected to Wi-Fi only (no Ethernet) while testing, and stay still in one spot for the duration of each measurement.

4. What each tab does

Run test

Pick a location name, duration, Wi-Fi band, and whether to include DNS/HTTP checks, then press Run measurement. Shows status, score, latency/loss/jitter/max, an RTT-over-time chart, and (if enabled) DNS/HTTP usability.

Compare locations

Bar chart of mean score ± 95% confidence interval per location (needs ≥ 2 runs per location for an interval), a run-to-run box plot, a 2.4 GHz vs 5 GHz comparison once you've tagged runs with a band, and the full session history.

Floor plan

Upload a photo or sketch of your space, click to place the router and each tested location, and get a color-coded coverage heatmap (green → red) once at least 2 locations are placed. Downloadable as PNG.

Report

Auto-generated summary: locations tested, status breakdown, potential dead zones, average latency/loss, usability breakdown, worst time of day, and per-location score ± CI. Downloadable as Markdown or CSV.

Monitor & trends

Runs repeated short probes over a set duration at one location, logs each cycle, and alerts when the score drops below your threshold. Below that: mean score by hour of day, a weekday × hour heatmap, and a scatter of every measurement over time.

5. Thresholds & scoring (tune these, they're not universal standards)

All defined in core.py under T and APP_T. Defaults:

StatusRule (on the primary target, usually the gateway)
Stableavg latency ≤ 50 ms, loss ≤ 1%, jitter ≤ 15 ms
Fairavg latency ≤ 100 ms, loss ≤ 5%, jitter ≤ 30 ms
Unstableanything worse than Fair, but not yet a dead zone
Potential Dead Zoneloss ≥ 10%, or completely unreachable

Score (0–100) is a weighted penalty: 40% loss, 35% latency, 25% jitter. Usability (DNS/HTTP) flags Degraded above 300 ms DNS or 1500 ms HTTP, and Unusable if HTTP fails entirely.

These numbers are starting points from the outline, not networking standards. After collecting real data, compare the app's classification against how the Wi-Fi actually felt at each spot (a speed test or video call), and adjust the numbers in core.py if needed — then say in your report why you chose the final values.

6. Where your data lives

  • Everything is stored locally in wifi_analyzer.db (SQLite) in the project folder — nothing leaves your laptop.
  • Tables: sessions (one row per test run), samples (every individual ping), monitor (continuous-monitoring cycles), floorplan (your uploaded image), coords (marker positions).
  • The Clear all measurements button (Compare tab) deletes sessions/samples/monitor logs only — your floor plan and marker positions are kept.
  • To start completely fresh, close Streamlit and delete wifi_analyzer.db.

7. Known limitations / parts you should verify yourself

I built and syntax-checked all files, and tested the scoring/classification/statistics logic with synthetic data. I could not run real network calls (ping, DNS, HTTP, live Wi-Fi bands) or the browser-based click widget in my sandbox — please verify these on your own machine before relying on them for your submission.
  • Ping output parsing assumes English-locale ping output. If your OS is set to another language, latency parsing may fail silently (falls back to wall-clock timing).
  • DNS timing can be optimistic on repeat runs because the OS caches lookups.
  • Floor-plan heatmap colors between your measured points are interpolated estimates, not real measurements — state this clearly if you present the heatmap.
  • Continuous monitoring blocks the Streamlit script while running — keep that browser tab open and the laptop awake; closing the tab stops logging.
  • Wi-Fi band is self-reported (you pick it from a dropdown) — the app does not auto-detect 2.4 vs 5 GHz.

8. Troubleshooting

SymptomLikely fix
Gateway shows NoneEnter it manually — find it via ipconfig (Windows) or ip route / route -n get default (Linux/macOS)
100% loss on everythingCheck ping works directly in your terminal; check firewall isn't blocking ICMP
streamlit-image-coordinates won't installSkip it — the Floor Plan tab falls back to X/Y sliders automatically
Monitoring tab seems frozenThat's expected — it's a blocking loop for the set duration. Wait it out or reduce "Total time"
Old database looks broken after updateIt shouldn't — db.init() auto-migrates old databases by adding new columns
